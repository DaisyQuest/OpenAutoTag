PDF Accessibility Engine
Version: tagging-quality-2026-10-23

Reviewed bookmarks and navigation preservation (A39-A40, 2026-10-23):
The additive reviewed-outline API/CLI accepts explicit source-hash-bound outline
decisions and appends Unicode hierarchical bookmarks with physical page targets.
It preserves existing authored navigation and verifies the complete saved
catalog/info graph against a fresh source replay before releasing a new output.
Independent inspection inventories outline graph relationships, explicit/named
destinations and logical page labels. Missing navigation evidence cannot pass;
only verified reviewed additions may change outlines, never labels or named
destinations. Invalid existing trees require review. Work and manifests are
bounded; signed/encrypted inputs are refused. The main pipeline does not infer
human acceptance. See docs/accessibility-50-batch23-20261023.md and the two
reviewed-outline contracts. Existing CLI arguments retain their behavior.

Native link grouping (A38, 2026-10-23):
Complete consecutive Span siblings belonging to one native annotation may be
grouped under one Link while retaining source ownership and each original ID.
One OBJR and reciprocal ParentTree entry associate the annotation. Logical child
order is verified independently of paint order. The additive groupedOwnerTagIds
field lists original members; ownerTagId identifies their common parent. Only
independently verified groups are transparent to intent parent/order comparison.
Partial spans, separate paragraphs, intervening content, authored replacements
and masking ancestors require review. Original content, controls and annotation
values are preserved. See docs/accessibility-50-batch22-20261023.md.

Native link geometry (A37, 2026-10-23):
Native Link hit testing uses unprojected source glyph displacement in default
user space. Simple counterclockwise QuadPoints, including concave/disjoint
regions, preserve original annotation values, actions and appearance. Rotated
pages, crop origins, UserUnit, rotated/sheared horizontal text and nested Forms
are qualified. Independent inspection carries additive quadPoints/linkPathPresent
evidence and uses consistent numeric serialization for exact rectangle edges.
Malformed/outside/ambiguous geometry stays for review. Quad count, source glyph
capture and geometry work are bounded. Cross-node anchor grouping remains A38.
See docs/accessibility-50-batch21-20261023.md.

Native link ownership (A36, 2026-10-23):
Native rewriting binds unambiguous source glyph ranges, Link elements, annotation
OBJRs and direct annotation ParentTree entries without changing anchor bytes,
spacing, actions or rectangles. The source-ownership contract exposes bound and
review_required nativeLinks. Saved validation independently proves exact source
coverage, annotation identity, reciprocal ownership and unchanged geometry/actions.
Only a generated leaf ActualText exactly equal to the complete source text may be
omitted to expose an inline Link; this exception is independently verified.
Authored/differing replacements, uncertain geometry and cross-node anchors stay
for review. Additional Link containers never gain blanket ownership exemptions.
Existing preservation fingerprints and CLI arguments remain compatible. Dedicated
quad/rotation qualification, multiline grouping and final eligibility integration
remain pending. See docs/accessibility-50-batch20-20261023.md.

Sampled editable font qualification (A35, 2026-10-23):
node modules/pdf-writer/editable-font-proof.js --pdf <candidate.pdf>
  --samples <source-bound-samples.json> --output-dir <fresh-directory>
The additive editable-font-samples/proof contracts bind exact source/request
bytes, field references, proposed values, embedded programs and saved QA copies.
Embedded simple TrueType and horizontal Type0/CIDFontType2 fonts qualify only
when encoding, independent embedded cmap, glyphs, Unicode and advances agree.
Generated /Tx text must match and fit its appearance clip. Fill/save/reopen
checks exact values, widgets, appearance bytes and PDFBox affected-page pixels.
Unsupported code points and behavior/layout uncertainty remain explicit. Only

0. Purpose

Build a contract-first PDF accessibility tagging pipeline with deterministic inference, qualified preservation repairs and independently checked saved outputs.

This repository is intentionally split into isolated modules. Each module is independently buildable, independently testable, and replaceable behind a fixed CLI and fixed JSON contracts.

1. Architecture rules

1. Contracts are the source of truth.
   Every module reads an input file and writes a contract-compliant output file or JSON payload to stdout.

2. No cross-module imports.
   Modules must not call each other as libraries. The orchestrator is responsible for process orchestration.

3. File ownership is strict.
   A module implementation only edits files under `modules/<module-name>/`.
   Shared files are limited to `contracts/`, `SPEC.txt`, `AGENTS.md`, root docs, test fixtures, and orchestrator files when explicitly assigned.

4. Deterministic rules before machine learning.
   Bootstrap implementations should prefer deterministic heuristics so outputs are stable and testable.

5. Replaceability matters more than local cleverness.
   If a better implementation later needs PDFBox, OCR, or a distributed queue, it must fit the same CLI and contract boundary.

2. Runtime model

Pipeline order:

1. `parser`
2. `layout-analyzer`
3. `semantic-engine`
4. `reading-order`
5. `tag-builder`
6. `font-embedder`
7. `pdf-writer`
8. `validator`

The orchestrator invokes each stage as a separate Node process and stores intermediate JSON artifacts in the job output directory.

2.1 Page geometry

New parser output declares source.coordinateSpace = "crop-display-points". Page dimensions, font sizes, text, image and widget boxes use physical points (1/72 inch), measured from the displayed CropBox top-left after page rotation and UserUnit. The page cropBox metadata remains in original PDF user coordinates; rotation and userUnit describe that source frame.

Layout analysis, semantic inference and reading order preserve the coordinate-space marker. Source-text and ruled-table diagnostics opt into the same frame. Mixed layout/table or layout/semantic-redaction frames reject rather than silently compare different coordinates. Semantic redaction plans declare their frame independently of overlay text.

PDFBox native operator positions already account for CropBox and Rotate; new matching scales these positions and glyph centers by UserUnit exactly once. Display-point matching requires explicit valid page dimensions, rotation, UserUnit and top-origin operators. Native tag plans record the resulting coordinate space. Saved plans without the marker retain the previous matching convention.

Raster writers map displayed images and invisible text back into original page coordinates, retaining CropBox, rotation and UserUnit. Redaction image coordinates use the declared frame. OCR render metadata reports physical displayed dimensions; this does not establish complete OCR orientation, recognition or attachment qualification.

3.3 Semantic engine

Command:
`node modules/semantic-engine/index.js <layout.enriched.json> > semantic.json`

Output:
`contracts/semantic.schema.json`

Aligned native label/value paragraphs may carry labelValuePairId and
labelValuePart (label or value); these optional fields must occur together.
Distinct pairs and parts are paragraph boundaries. Inference precedes quotation
detection, requires colon or repeated alignment evidence, and emits precedes
relations through wrapped values. It excludes explicit semantic groups, tables,
form-linked text, OCR and unsupported directions; crowded pages receive a review
task. Both paragraph-merger strategies retain the identities and reconstruct
qualified touching fragments without adding spaces inside words. These are
reviewable inferences, not a declaration of correct semantics for every row.

Running-content inference requires cross-page sequence or repeated detached-margin
evidence and emits artifactEvidence plus review tasks. It protects meaningful
headings, body text, explicit semantic groups, OCR and nearby form prompts. A
numbered blank separator may inherit an established pagination sequence; a set
of number-only cards is not automatically discarded as running content.

Numeric prefixes shared by heading-rank and style-anchor inference distinguish
supported section numbers from dates, measurements and versions. Body-sized
numeric content and explicit list membership retain their appropriate roles.
Qualified heading continuation may cross bold faces while preserving subtitle,
rank, size, alignment and intervening-content boundaries.

3.4 Reading order

Command:
`node modules/reading-order/index.js <semantic.json> > semantic.ordered.json`

Output:
`contracts/semantic.schema.json`

Reading order synchronizes headingLevel to final H1-H6 roles and rebuilds outline
parents in final reading order. Non-headings lose stale headingLevel metadata.
Tag construction likewise treats the final role as authoritative even when an
imported correction still carries old detection metadata. Existing heading
normalization and clamp adjustments remain explicit review information.

3.5 Tag builder

Command:
`node modules/tag-builder/index.js <semantic.ordered.json> > tagging.json`

Output:
`contracts/tagging.schema.json`

Qualified paragraph and list continuations retain each semantic content identity
under one P or LBody. Table header associations are enabled by default; explicit
enableTableHeaders=false or TAG_BUILDER_ENABLE_TABLE_HEADERS=0 retains the legacy
output. Grouped headers, preceding row/column headers and repeated occurrences
receive table-scoped IDs. Both native and raster writers emit Headers, IDTree,
Scope and list numbering, rejecting dangling or cross-table header references.

3.6 Font embedder

Command:
`node modules/font-embedder/index.js --pdf <input.pdf> --tags <tagging.json> --output <fonts.json>`

Output:
`contracts/font-inventory.schema.json`

Analyzes every font resource in the source PDF, detects embedding status,
Standard-14 references, ToUnicode coverage, encoding, and CID system info.
Reconstructs missing ToUnicode maps from TTF cmap tables, Type1 Differences
arrays, Adobe Glyph List, or CID Registry/Ordering/Supplement. Reads OS/2
fsType for a warning-only license flag. Emits a per-font remediation plan
(embed-as-is, inject-to-unicode, substitute-fallback, subset-and-embed,
rewrite-encoding, re-embed-from-cache, synthesize-type0-wrapper).
These actions describe proposed work. The writer does not execute every action;
an inventory entry must never be reported as a completed saved-PDF repair.
The explicit qualified font-repair CLI is described in section 3.7a.

Licensing is advisory only: fsType bits are surfaced in license.flag but
never block embedding. See FLAG in README for future policy work.

3.7 PDF writer

Command:
`node modules/pdf-writer/index.js --pdf <input.pdf> --tags <tagging.json> --semantic <semantic.ordered.json> --output <tagged.pdf> [--mode auto|native|raster] > writer-report.json`

Output:
Writer report JSON plus output artifacts at the provided path.

Writer modes:
Native operator tagging is implemented. Auto mode probes the input and selects
native tagging, preservation of qualifying already-tagged input, or raster
reconstruction. The report records the effective mode and fallback reason.
Existing-tag preservation defaults to incremental metadata/qualified repairs;
new semantic inference is not wholesale written over the authored tree.
Raster reconstruction embeds its overlay font (bundled Noto Sans by default),
but that does not guarantee preservation of editable forms or native content.
Missing semantic context can produce a sidecar-only copy; inspect writerMode
and nativeTaggingApplied before claiming that tags were written.

3.7a Qualified font repair (opt-in post-processing)

Command:
`node modules/pdf-writer/font-repair.js --pdf <preserved.pdf> --output <candidate.pdf> > font-repair.json`

Verification only:
`node modules/pdf-writer/font-repair.js --pdf <preserved.pdf> --verify <candidate.pdf> > font-proof.json`

Output: `contracts/font-repair-report.schema.json`. Extends the existing
per-object repair ledger with exact source/candidate hashes and a saved-object
verification result. No existing CLI contract changes. The pass is explicit,
not automatically enabled by production-checks. Output must not already exist.

Qualified rules embed pinned PDF.js standard-font CFF programs for canonical
ZapfDingbats and observed whitespace-only Times-Roman outside editable form
resources, and complete existing CIDSet bitmaps for embedded TrueType fonts
with explicit Identity CIDToGIDMap. Custom fonts/mappings remain for review.
Existing font programs, page and appearance commands, field values, widget
states and structure are preserved. Saved objects are compared against a fresh
replay of only these repairs. Encrypted/signed input is outside this pass.

Additional editable-default rules add missing ToUnicode only to embedded,
nonsymbolic TrueType fonts with explicit WinAnsiEncoding after checking every
defined encoding/glyph/Unicode mapping against the existing program. An unused
bare Helvetica AcroForm default can reuse one existing authored Arial program
only after complete page/appearance usage scanning and matching every defined
glyph and advance. The original encoding and all 256 advances are retained.
This does not supply an external fallback font or qualify arbitrary defaults.

`scripts/check-pdf-preservation.js --font-repairs true` independently invokes
the verification CLI on its source and candidate. Only exact hash-bound proof
permits the expected resource fingerprint changes. Other preservation checks,
mandatory validation and the review-only disposition remain in force.

The verified-symbol-unicode rule adds absent ToUnicode to qualifying symbolic
embedded TrueType Type0 fonts with Identity-H/V, explicit Identity CIDToGIDMap
and complete observed usage. Unique nonprivate embedded Unicode cmap evidence
or an audited outline/units/advance fingerprint identifies each used glyph.
The current fallback fingerprint is Wingdings index 118 / U+2756; font names
and code values alone are not evidence. Conflicting aliases, unsupported glyphs,
editable defaults and any authored ActualText remain for review. Existing maps,
including empty/malformed entries, are preserved. Programs and painting are
unchanged and source replay verifies the full graph. Run before parsing/tagging
so regenerated intent and ActualText use the corrected extraction. See batch 16.

Optional --donors <manifest.json> enables exact-truetype-program-recovery.
contracts/font-donors.schema.json binds the source hash, target font references,
program paths (relative to the manifest or absolute), and program hashes. Limit:
256 KiB manifest, 32 donors, 64 MiB/program and 128 MiB combined. Duplicate/stale
or unreachable targets reject. The report adds optional donorManifestHash.
Only simple nonsymbolic TrueType fonts with complete observed usage outside
editable defaults qualify. The full donor must match the PostScript identity
and exact bytes of the program currently resolved by PDFBox. All used glyphs,
Unicode, advances, outlines and effective paint scaling must agree. Programs
must permit installable/editable outline embedding; no permission is modified.
Variable/unsupported programs, existing program entries and uncertain cases
remain for review. Shared descriptors are isolated only for requested fonts.
This proves the tested environment's resolved program, not original author
provenance or every reader's substitution. See batch 17 and its evidence.
Preservation replay accepts --font-donors <manifest.json> together with
--font-repairs true. Donor inputs are protected from report output overwrites.

Optional --repair-unicode true enables direct ToUnicode diagnostics and the
verified-invalid-unicode rule. The report adds unicodeDiagnostics with each
font's source state, usage completeness, used-code count, per-code mappings,
independent expected values where known, reasons and whether a repair applied.
States distinguish absent, malformed, incomplete, contradictory, valid syntax
and unsupported syntax. A parsed/valid map is not proof of semantic accuracy.
The bounded parser supports one-byte simple-font and two-byte Identity CMaps,
bfchar, scalar/array bfrange and UTF-16BE sequences. Limits: 4 MiB map data,
200,000 tokens, 65,536 definitions, 512 bytes/destination, 256 diagnostic fonts,
4,096 observed codes/font and 32,768 observed diagnostic codes/document.
Later code definitions supersede earlier ones; codespaces are checked per byte.
Inherited/custom CMaps, ambiguous syntax and limits remain for review. Invalid
unused entries also require separate evidence.
Only qualifying embedded TrueType glyphs with unambiguous embedded Unicode
cmap or the documented symbol fingerprint can supply a replacement. All used
glyph IDs, widths, displacements, vertical origins and outlines must remain
equal. Valid authored entries, including unused Unicode sequences, are kept.
Conflicting valid mappings, editable defaults, incomplete usage and authored
ActualText prevent automatic replacement. Apply before parsing/tagging.
Saved-object replay must use the same --repair-unicode true flag; preservation
verification forwards it only with --font-repairs true. Default calls retain
existing-map preservation. Source/candidate hashes still bind the proof.

Font audit toUnicodeCoverage/mappedGlyphCount now describe direct CMap coverage,
not PDFBox fallback extraction. toUnicodeStatus is absent/malformed/parsed;
parsed is not strict syntax or semantic qualification. unmappedCodes records
missing direct mappings, and standardFallbackCodes separately reports qualified
simple-font standard encodings. Missing/incomplete maps with complete observed
standard fallback produce warnings; missing codes without such evidence remain
errors even above 99% coverage. Empty/unreadable maps produce an explicit
TO_UNICODE_MALFORMED error. This audit is not a complete font conformance checker.

3.7b Qualified link repair (opt-in post-processing)

Command:
`node modules/pdf-writer/link-repair.js --pdf <preserved.pdf> --output <candidate.pdf> > link-repair.json`

Verification only:
`node modules/pdf-writer/link-repair.js --pdf <preserved.pdf> --verify <candidate.pdf> > link-proof.json`

Output: the existing `contracts/repair-audit.schema.json`. The audit is emitted
only after exact saved-object verification succeeds. No overwrite is allowed.
Only link descriptions, qualified ownership and the necessary ParentTree and
structure-child entries change. The normal strict preservation gate applies.

Blank descriptions may be filled from an unchanged simple URI action. Existing
same-URI overlap binding now checks the anchor's reciprocal ParentTree entry
and rejects compound actions. Different URI actions can receive a separate
adjacent Link only when the extracted URL/email text matches that action and
one strongly overlapping authored Link has the same extracted text and a
qualified containing structure. Rotated pages, QuadPoints, hidden links,
ambiguous/stale ownership and unsupported actions stay for review. Existing
annotation order, rectangles, actions, resources and form objects are retained.

These rules also run under the existing PASSTHROUGH_REPAIR_LINKS switch. The
explicit CLI can follow font remediation without rerunning metadata or other
writer transformations. Its exact graph verifier is shared with the font pass.

3.7c Qualified structure metadata repair (opt-in post-processing)

Command:
`node modules/pdf-writer/structure-repair.js --pdf <preserved.pdf> --output <candidate.pdf>`

Verification only: replace `--output` with `--verify`. Both commands emit the
existing contracts/repair-audit.schema.json only after exact saved-object replay
verification. The CLI never overwrites its input or an existing output.

Numbered headings are compacted with a single monotone rank mapping only if
the resulting complete sequence begins at H1 and has no downward level skips.
Equal levels remain equal, and existing heading membership/content is retained.
Generic/mixed headings and ambiguous sequences stay for review. Valid custom
RoleMap chains are resolved without editing the RoleMap.

Optional repeated `--figure "<object> <generation> R" "<reviewed description>"`
arguments require `--source-sha256 <exact source hash>`. Each target must be an
unmapped Artifact leaf with no existing Alt/ActualText, unique reciprocal page
MCID ownership, and exactly one image XObject invocation. Text, Form XObjects,
inline images, conflicting/nested semantic content and stale decisions fail
closed. Bare Clip/ClipSpan wrappers are allowed. Review is required to decide
whether a graphic is meaningful and to supply its description; this pass does
not guess descriptions or convert arbitrary Artifact tags into standard roles.

Repeated --paragraph "<object> <generation> R" decisions also require the exact
--source-sha256. Each reviewed heading must own one unique reciprocal page MCID,
with only layout attributes/classes and optional existing Form children. Only
its S changes to P; content, fields and ownership stay intact. For fresh gate
verification supply --structure-repairs true --structure-decisions <json>, where
the file contains {"sourceSha256":"<hash>","paragraphs":["<object> <generation> R"]}.

Without Form splitting, only approved /S and /Alt entries change. Optional
`--split-forms true` splits bare Form elements containing multiple OBJRs for
distinct terminal fields into consecutive Form siblings. Authored semantic
attributes, mixed children, shared fields and ambiguous ownership stay for
review. Existing OBJRs, fields, widget dictionaries and annotation slots are
retained; only structure child/parent relations and reciprocal ParentTree
targets change. The original Form and its ID remain with its first widget.

`scripts/check-pdf-preservation.js --structure-repairs true` independently
replays this bounded repair against the source and saved candidate. Only fresh,
hash-bound proof permits the corresponding Form owner changes; field/content,
appearance and other preservation checks still apply. This gate option covers
Form splitting and heading compaction, not reviewed figure decisions.

Content streams, resources, fields, widget appearances, annotation actions,
metadata and IDTree are preserved. Signed, encrypted and PDF 2.x/namespaced
documents are outside scope. This explicit pass does not enable legacy broad
passthrough transformations or alter validator rules.

3.8 Validator

Command:
`node modules/validator/index.js --pdf <tagged.pdf> --manifest <tagged.pdf.tags.json> > validation-report.json`

Output:
Validation report JSON. Bootstrap validation checks contract completeness, native PDF structure markers, metadata, and known PDF/UA blockers.

The pinned validator is veraPDF 1.30.3 Greenfield. Install using
`node scripts/install-verapdf.js`; the installer verifies a pinned SHA-256,
stages and version-checks the CLI, and retains the previous installation before
replacement. Portable/bootstrap installers use the same release and checksum.
PDFBox 3.0.8 is separately vendored for writing, inspection and font auditing;
the diagnostic probe no longer depends on the discontinued veraPDF PDFBox CLI.

Raw veraPDF results are authoritative: `summary` equals `rawSummary`, and
`rawFindings` retains rule contexts and messages. No raw failure is suppressed.
Independent metadata, Link/Widget ownership and Form child-rule probes provide
diagnostics only. Overall success requires a compliant veraPDF result and no
manifest/font-audit findings or execution error. Separate font-audit failures
remain blocking even when the raw veraPDF result passes.

4. Shared contracts

Contracts live under `contracts/`.

- semantic-benchmark.schema.json validates independent regression references.
  npm run benchmark:semantic executes real semantic, ordering and tag-builder
  CLIs and reports per-dimension checks and content ownership. References record
  provenance and expert review status. npm run qualify:semantic -- --pdf <file>
  --reader-evidence <record.json> additionally requires completed reference review
  and candidate-bound human evidence with reader and PDF viewer versions.
  Missing qualification returns review_required and exit code 2; synthetic
  references are never represented as human reader observations.

- `layout.schema.json`
  Raw and enriched geometric text blocks from the source PDF.

- `semantic.schema.json`
  Deterministic semantic roles and reading-order annotations.

- `tagging.schema.json`
  Hierarchical logical structure to drive PDF writing. Optional
  `fontInventoryRef` field points pdf-writer at a font-inventory document.

- `font-inventory.schema.json`
  Per-document font inventory with per-font remediation plan, produced by
  font-embedder and consumed by pdf-writer.

- `pipeline-job.schema.json`
  Queue and API contract for orchestrator job status.

Contracts are reviewed before implementation; compatible extensions are additive
and schema-tested. Proposed roadmap fields are not part of the implemented API.

8. Definition of done

Bootstrap done:

- All contracts are in place
- All modules expose stable CLIs
- Tests pass
- Orchestrator can process a sample PDF end-to-end

Production qualification requirements (not all completed):

- Native structure and intended semantics survive serialization and reopening.
- Raw validation and the independent font audit pass for the exact candidate.
- Fields, appearances, links and content pass the applicable preservation proofs.
- Independently reviewed references and a held-out real-document corpus establish
  per-feature accuracy and explicit unsupported cases.
- Candidate-bound human reader/keyboard observations cover intended viewers.
- Operational limits, packaging, failure handling and rollback are qualified.

The current TEST-FORM candidate remains review_required. Synthetic regression
success and one validated document do not establish general accuracy, full
PDF/UA conformance, WCAG conformance or universal viewer compatibility.
Typed accuracy-corpus and saved-semantics contracts now support the real-PDF
pilot and reopened structural comparison. Rebuilt production candidates must
agree with emitted intent; preserved repairs retain exact replay verification.
Saved semantic inspection independently parses executed page and Form content.
The additive markedContent inventory records stream-scoped sequence counts,
decoded glyph counts, meaningful/unknown glyph counts and graphics operations.
Named property resources, page content arrays, font state and invoked Forms are
resolved with bounded bytes, operations, glyphs, state depth and recursion.
Missing/duplicate/unbalanced sequences reject; structure references alone cannot
prove attachment. Nonempty intended text requires owned, decoded non-whitespace
glyphs. ActualText alone, Artifact paint, unknown glyphs and graphics-only content
cannot satisfy that text check. Graphic roles and blank synthetic cells retain
separate rules. Legacy inspection JSON remains readable, but saved comparison
without the new content evidence rejects rather than granting a legacy pass.
ParentTree entries resolve reciprocally to page, invoked Form and OBJR scopes;
scope keys must be integral, unique and correctly typed. Extra live entries,
missing keys, conflicting StructParent/StructParents and wrong owners reject.
Native output additionally writes <output>.ownership.json under the public
source-ownership schema. It binds the source PDF and exact tagging intent bytes
by SHA-256 and records proposed tag owners for original source glyph ranges.
Ranges use page number, invocation path, lexical operator index and relative
glyph offsets. List-prefix and compound-operator partitions retain their exact
source offsets. This intent is not independent semantic classification proof.
The saved checker accepts additive --source-pdf and --ownership arguments,
required together with --tags; production native validation requires both.
Independent source/saved scans compare font names and character-code sequences,
raw glyph rendering matrices and displacement (0.001 tolerance), and each glyph's
intended owner. Anonymous authored Span containers resolve to their intended
ancestor; duplicate, foreign and nested ownership reject. Reports bind source,
candidate, intent and ownership hashes and expose ownershipStatus. Tag-only
checks remain available but do not qualify source ownership.
The additive textRuns, positions, replacementScopes and actualTextPresent
inspection evidence supports complete normalized text comparison in saved
structure order. Partial matches cannot pass; an empty ActualText cannot silently
suppress an intended node. NFKC and whitespace normalization do not establish word
boundaries. Replacement exceptions require unchanged authored text on the exact
continuous source range, or complete identical overprints at identical positions
with the intended saved ActualText and verified source ownership. Arbitrary
generated replacement text cannot conceal lost glyphs. These checks do not prove
font-program equivalence, visibility, clipping, annotation appearance text, OCR
completeness, correct source semantic classification or reader behavior. The
bounded inspector fails explicitly on unsupported traversal/output limits.
Paragraph merging must retain source identities and rebind semantic references.
Heuristic evidence is not a calibrated probability. Multilingual expansion is
lower priority than the preservation and semantic qualification gates.
OCR rendering uses physical DPI including UserUnit, with CropBox and page
rotation applied by the renderer. Its explicit pixelToDisplay matrix uses the
actual rendering scale, never a ratio inferred from rounded bitmap dimensions.
Tesseract deskew is inverted once about the integer image center before display
coordinates are emitted. Layout text blocks may carry typed ocrGeometry evidence:
image size, recognition angle, original pixel box, inverse transform, display
quadrilateral and clipping flag. Missing/mismatched frames or invalid boxes fail
the recognition candidate. Clipped geometry is explicit and is not acceptance.
Raster variants are bounded to 36-1200 DPI, 40 million pixels and 32768 pixels
per side. Oversized pages reject rather than silently changing the requested DPI.
Geometry evidence does not certify recognized words. Semantic ocrSegments retain
the original recognized lines and geometry through paragraph/heading merges;
native and OCR nodes cannot merge across their provenance boundary. Tagging
ocrSegments declare each emitted line's page, source identity, exact text and
display quadrilateral. List labels and bodies receive disjoint line portions.
The native writer appends embedded, invisible (Tr=3) OCR text to original pages,
with a real MCID owner and reset graphics context. It never matches OCR nodes
against native operators. Image-only pages can use native mode when explicit OCR
geometry is available; missing geometry, invalid quads or unsupported font glyphs
reject before save. Source images, native paint and form appearances remain in
place. OCR-only regions may be added without exceeding the native character
count; overlaps retain native text and preserve both transcriptions, geometry and
semantic-node references in review tasks, including retained-native decisions.
Saved ownership checks treat generated OCR as a separately verified page suffix.
Every original source glyph still requires its original code, position and owner.
Each declared OCR segment requires exact decoded Unicode, an embedded font,
invisible rendering mode, exclusive tag ownership and the intended line envelope
with continuous glyph advances (0.02 display-point tolerance). Undeclared,
missing, visible, shifted, partial and misowned generated text reject. The tagging
intent hash binds the OCR declaration. Typed PDFBox serialization bypasses GSUB
ligature substitution for invisible OCR; it does not normalize recognized text.
OCR font selection uses the bundled Noto Sans, Noto Sans Symbols and Noto Sans
Symbols 2 programs in that order, with cached code-point coverage and adjacent
runs sharing a font. Multiple font runs retain one line MCID and one continuous
text matrix; the total verified font advance fits the declared line envelope.
Saved validation joins runs only within a continuous, exclusively owned MCID
