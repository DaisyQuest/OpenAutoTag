# Accessibility engine: 50-improvement delivery ledger

Started 2026-10-22 from `eff2da8`. The active objective is to implement and verify **all 50** improvements below. Previous deliveries are the baseline and are not credited toward these 50. Status and evidence are maintained in [the machine-readable ledger](evidence/accessibility-50-status.json).

Research establishes requirements, not proof of our implementation. The engineering choices below combine observed repository gaps with these primary sources:

- [PDF Association Matterhorn Protocol 1.1](https://pdfa.org/wp-content/uploads/2021/04/Matterhorn-Protocol-1-1.pdf): separate machine-checkable failures from matters needing human judgment.
- [ISO 32000-2 document interchange errata](https://pdf-issues.pdfa.org/32000-2-2020/clause14.html) and [text errata](https://pdf-issues.pdfa.org/32000-2-2020/clause09.html): structure/content relationships, text operators, fonts and Unicode. PDF 2.0 findings inform version-aware handling; they are not a claim of PDF/UA-2 support.
- W3C techniques for [reading/tab order (PDF3)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF3), [tables (PDF6)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF6), [OCR (PDF7)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF7), [headings (PDF9)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF9), [links (PDF11)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF11), [forms (PDF12)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF12), and [bookmarks (PDF2)](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF2). These are techniques, not certification criteria by themselves.
- [Apache PDFBox 3.0.8 PDFStreamEngine source](https://raw.githubusercontent.com/apache/pdfbox/3.0.8/pdfbox/src/main/java/org/apache/pdfbox/contentstream/PDFStreamEngine.java): implementation behavior must be distinguished from lexical source operations.

Completion requires an actual engine improvement, targeted positive/adversarial tests, saved-PDF verification where relevant, and appropriate real-document replay. Preserve source appearance, editable controls and raw findings. Do not mark an item resolved by weakening a gate or replacing its requested capability with rejection. Human review remains required for final document acceptance.

## Selected improvements

| ID | Area / improvement | Acceptance evidence required |

| A01 | Native operators: **Lexical operator indices**. Keep source operator indices exact when PDFBox dispatches virtual TD/TL operations. | Mixed positioning/text fixture indices equal an independent PDFStreamParser token walk. |
| A02 | Native operators: **Quoted text operators**. Treat single-quote and double-quote text showing as one source operation each. | Quote operators decode complete text once and subsequent native tags own the correct glyphs. |
| A03 | Native operators: **Nested stream identity**. Report Form XObject invocation paths separately from page text operators. | Nested/reused Forms carry stable invocation identities; no child operator impersonates page text. |
| A04 | Native operators: **Native Form XObject tagging**. Tag text in nested and reused Form XObjects with invocation-specific ownership. | Saved text in two differently transformed invocations has correct owners and unchanged pixels. |
| A05 | Native operators: **Stream-scoped MCR emission**. Write stream references and scoped ParentTree entries for non-page content. | Identical MCID numbers in different streams resolve to their own structure elements. |
| A06 | Native operators: **Standalone list marker attachment**. Attach a marker-only source operator to Lbl and following content to LBody. | Separate marker/body operands yield nonempty saved Lbl and LBody without moving glyphs. |
| A07 | Native operators: **Array-based list marker splitting**. Split qualified TJ list markers while retaining all positioning adjustments. | Mixed string/number TJ arrays preserve advances, bytes and distinct label/body ownership. |
| A08 | Native operators: **Compound text-node attachment**. Partition one source text operation across multiple intended label/value nodes. | Booklet label/value examples attach to exact intended nodes; spacing and geometry are unchanged. |
